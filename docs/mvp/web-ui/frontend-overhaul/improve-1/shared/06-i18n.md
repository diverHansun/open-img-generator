# 多语言（i18n）

## 1. 目标与范围

UI 默认中文，可切换英文。本方案只覆盖界面文案（按钮、标题、状态、错误、空态、辅助说明），不覆盖：Provider/Model/credential 名称等专有数据、UUID、后端返回的错误 message 原文、日志。

不做：URL 级语言路由（`/zh/...`）、服务端语言协商、复数规则引擎、RTL、日期本地化库、明暗主题切换。

## 2. 技术方案

轻量 React context + 字典，不引入 next-intl 等路由级方案：

```text
src/lib/i18n/
├── zh-CN.ts        # 中文字典（默认）
├── en.ts           # 英文字典
├── types.ts        # Dictionary 类型（以 zh-CN 为基准 shape）
└── index.ts        # t() 与字典加载

src/components/i18n/
├── LocaleProvider.tsx   # context：当前 locale + setLocale
└── LocaleSwitcher.tsx   # 切换控件（两种壳复用）
```

- 默认 locale = `zh-CN`；用户切换后写入 localStorage `locale`，刷新后恢复。
- 不读取 `navigator.language` 做自动推断（默认中文是产品决策）。
- `t(key)` 支持 `{name}` 形式的插值；不支持的 key 在开发态报警并回退显示 key 本身。
- 字典为普通 TS 对象，按类型保证两种语言 shape 一致；不按 locale 动态 import（两本字典体量小，同步加载）。

## 3. 切换入口

- Home：顶部品牌条右侧。
- Workspace 壳：侧边栏底部（桌面）/ 抽屉内底部（移动）。

切换即时生效（不重载页面、不发请求），焦点保持在控件上；控件有 `aria-label`（如"切换语言 / Switch language"）。

视觉上使用无底板的 `中文 / EN` 文字切换：外层不绘制白色 surface、边框、阴影或胶囊背景，当前语言只用字重与单色下划线标记；hover/focus 不改变布局。桌面侧栏、Home 顶栏与移动抽屉复用同一表现。

## 4. 文案规范

1. 所有用户可见字符串必须走 `t()`，组件内禁止硬编码中英文。
2. 保持原文的数据类内容不翻译：Provider display name、model ID、credential name（如 `FAL_KEY`）、Workspace/Session 用户命名、Prompt 内容。
3. key 按页面/域组织，lowerCamel 命名：

```ts
{
  common: { save, cancel, retry, loading, ... },
  shell: { backToWorkspaces, generate, history, ... },
  home: { title, createPlaceholder, recentTitle, ... },
  generate: { compose, stage, currentTask, viewProgress, backToEdit, jobDetails, ... },
  history: { ... },
  gallery: { ... },
  models: { ... },
  providers: { ... },
  providerDetail: { ... },
  dialogs: { detailTitle, viewGenerationDetail, ... },
}
```

4. 复数/数量表达用中性句式（如"共 {count} 张图片"），避免引入复数规则。
5. 相对时间（"2 小时前"）由统一 `formatRelativeTime(ts, locale)` 输出，两种语言各一套模板，不引入日期库。
6. 状态文案（Configured / Not configured / pending / failed 等）集中在 `common.status.*`，七个路由页面及弹层复用同一映射。

## 5. 测试与验收

- unit：zh-CN 与 en 字典 key 集合完全一致（递归比较）；`t()` 插值与缺失回退行为。
- 人工：切换语言后主流程文案全部随行；无明显排版溢出（英文普遍更长，重点检查按钮、表格头、侧栏）。
- 静态抽查：页面组件无裸露中文字符串。
