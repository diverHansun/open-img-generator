# 讨论记录与已确认要点

> 2026-07-21 与用户讨论定稿。本文只冻结已确认结论；原因与证据见 01，实施契约见 02。

## 1. 背景与动机

用户在真实浏览器操作中多次遇到“生成图片未能安全保存”：Provider 已返回远端图片 URL，但本机代理/TUN 的 DNS fake-IP、CDN 主机变化或网络路径使转存失败。与此同时，服务重启后曾出现历史图片无法显示，暴露出现有“图片文件、图片 DB 行、生成历史”语义耦合过紧的问题。

产品约束已经明确为本机单实例、单用户，核心价值是用简单可靠的方式聚合多个生图 Provider，而不是发展为通用网络代理或云端资产管理系统。因此本批优先减少不必要的远端下载，并建立短期本地资产与长期生成历史之间的清晰边界。

## 2. 已确认：目标与产品语义

| 决策项 | 已确认结论 |
|---|---|
| 运行形态 | 本机单实例、单用户 |
| 未收藏保留期 | 图片生成成功后默认保留 7 天；需要更长时间时可自行配置 |
| 收藏/保留 | 收藏图片持续保留，直到用户主动删除 |
| 取消收藏 | 恢复按图片生成时间计算的 7 天规则；图片已超过 7 天时可在下一轮清理中移除 |
| 下载/导出 | 保存一份副本到用户选择的位置；应用内部副本仍按 7 天规则清理；下载不续期 |
| 历史记录 | 自动 retention 与单图删除后，任务、提示词、Provider 错误、Generation/Job 记录继续保留；用户另行明确执行“删除整条 Generation”时除外 |
| 清理后的展示 | 不把整条历史删除；明确显示“图片已过期清理”，并与 Provider 空结果/保存失败区分 |
| 主动删除 | 与“取消收藏”分开；主动删除立即移除应用内文件，但保留“用户已删除”历史墓碑 |
| 文件缺失 | 非正常缺失不得伪装成过期；历史显示“本地图片文件不存在”，便于排查外部删除/目录变更 |

## 3. 已确认：Provider 与存储边界

| 决策项 | 已确认结论 |
|---|---|
| 内联优先 | 官方响应支持且不破坏现有任务生命周期时，优先请求 Base64/Data URI |
| ZenMux | 保持现有 Base64 优先实际行为，同时兼容 URL fallback |
| 豆包 | 请求 `b64_json`，同时保留对 URL 响应的解析兼容 |
| fal | 保持 queue/poll + URL 转存；不为 Data URI 切换到会改变历史/恢复语义的 `sync_mode=true` |
| URL-only Provider | SiliconFlow、智谱、通义千问、可灵及 fal 完成后立即安全转存，不延迟到用户浏览时下载 |
| SQLite | 只保存任务与图片元数据/墓碑，不保存图片 BLOB 或 Base64 原文 |
| 文件系统 | 图片字节继续存放在 `LOCAL_STORAGE_DIR`（默认 `./data/images`） |
| 远端链接有效期 | 只决定“必须立即转存”，不决定本地图片保留多久 |

## 4. 已确认：网络层边界

| 项 | 结论 |
|---|---|
| 通用代理层 | 不建设自动代理发现、端口扫描、PAC/SOCKS/HTTP 路由或多代理故障转移框架 |
| 当前 Node 服务 | 保持现有安全下载路径与必要的精确 host/fake-IP 过渡兼容；不承诺浏览器代理自动等于后端代理 |
| 未来 App | 打包技术确定后优先复用宿主系统网络栈、系统证书和系统代理能力，而不是自研网络路由 |
| 安全边界 | 不因兼容网络而全局放开 private/reserved 地址或取消远端图片 SSRF 校验 |

## 5. 已确认：配置与操作语义

- `IMAGE_RETENTION_DAYS` 默认从 `30` 改为 `7`。
- `0` 表示关闭未收藏图片自动清理；合法正整数表示保留天数；非法值安全回退为 7 并产生不含敏感数据的警告。
- 当前 Web 版本使用浏览器标准下载；是否弹出保存位置由浏览器设置决定。
- 未来 App 使用系统“另存为”对话框。本批不绑定 Electron、Tauri 或其他宿主。
- 下载行为不写 `downloaded_at`，不改变收藏状态，也不成为永久保留凭据。

## 6. 已确认：本批不做

| 项 | 不做原因 |
|---|---|
| 把图片存入 SQLite BLOB | 增大数据库、迁移和备份成本；当前文件系统边界足够 |
| Provider SDK 全量迁移 | SDK 不能改变厂商输出契约，且可能引入隐藏重试/网络语义 |
| 按浏览时间延长保留期 | 产生隐式状态与不可预测的磁盘增长 |
| 回收站 | 增加第二套保留生命周期，当前需求没有证明其收益 |
| 下载历史/导出审计 | 本机单用户场景没有当前业务价值 |
| 复杂磁盘配额 | 先以 7 天清理和明确磁盘错误满足需求；有使用数据后再评估 |
| Provider 独立保留期 | 本地策略是统一产品语义，不跟随上游 URL 寿命 |

## 8. 用户确认记录

用户逐项确认：未收藏 7 天且可配置、收藏永久保留直到主动删除、下载不延长内部期限、历史继续保留并显示过期、拒绝庞大代理层、未来 App 优先复用系统网络栈；随后确认采用图片墓碑、生成时间计时、取消收藏后可立即进入清理、当前环境变量配置与未来 App 设置分阶段落地。
