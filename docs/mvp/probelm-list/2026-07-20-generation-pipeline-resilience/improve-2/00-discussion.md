# 讨论记录与已确认要点

> 2026-07-20 与用户确认。本目录其余文档给出基线、实施契约和验收标准。

## 背景与动机

浏览器连续提交后，fal Job 显示“生成图片未能安全保存”，ZenMux Job 显示“暂时无法确认服务商是否已接纳当前任务”。只读检查证明前者是本机代理/TUN 的 DNS fake-IP 与远端图片安全策略冲突；后者与同步图片生成的 30 秒请求预算相符。

## 已确认：目标与范围

| 决策项 | 已确认结论 |
|---|---|
| 同步生成 timeout | 所有同步图片生成 Provider 使用三分钟上限，而非仅修 ZenMux |
| 代理兼容 | 支持关闭和开启代理两种运行环境；不得用关闭 SSRF 防护换取可用性 |
| 代理安全边界 | 精确主机白名单与固定 `198.18.0.0/15` 代理映射段共同成立才例外通过 |
| 默认行为 | 未配置白名单时维持当前公网 HTTPS-only 拒绝策略 |
| SDK | 本批不迁移官方 SDK；先修复项目自己的网络与持久化边界 |
| 验证 | 先自动化验证，再启动真实服务、用浏览器调用真实 Provider；完成后不关闭服务，等待用户继续测试 |
| Git | 实施按可验证的 P1/P2/P3 分批 commit；不混入既有 UI 工作树改动 |

## 已确认：不做的事

| 项 | 本批结论 |
|---|---|
| `ALLOW_PRIVATE_IMAGE_URLS=true` | 不作为代理兼容方案；它会对所有 Provider 放宽安全边界 |
| 白名单形式 | 不支持 `*.fal.media`、正则或任意 CIDR；只支持规范化后的精确 hostname |
| `outcome_unknown` 重试 | 不恢复、不自动重投既有或未来结果未知请求 |
| SDK 迁移 | fal SDK 与 OpenAI SDK 仅作调研对比，不纳入本批 |
| 自动真实付费测试 | 不进入 CI 或默认命令；只做用户授权的一次受控浏览器 flow |

## 与关联议题的关系

- `improve-1` 已建立持久化 Job/lease、结果未知不重投、远端 URL 安全校验和安全错误 DTO；本批只修复其在透明代理环境下的兼容缺口，不改变这些原则。
- `docs/test-blueprint.md` 仍是测试分层与真实 Provider opt-in 的项目级规则。

## 用户确认记录

用户确认采用“同步 Provider 统一三分钟 + 代理精确白名单”，并要求完成后启动服务进行真实 Provider 浏览器 E2E、保留服务运行以便继续测试。
