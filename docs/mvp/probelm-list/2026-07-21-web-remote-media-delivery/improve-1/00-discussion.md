# 0. 讨论结论

## 0.1 背景

当前应用在 Provider 已经生成图片后，还要求 Node 后端立即下载远程图片、校验并写入 `LOCAL_STORAGE_DIR`。Qwen、Zhipu、SiliconFlow 等媒体 CDN 可能在本机代理、路由器 Nikki/Mihomo Fake-IP 或 DNS 模式下解析为保留地址；后端 SSRF 防护会正确拒绝这些地址，于是用户看到“生成图片未能安全保存”，尽管 Provider 生成本身已经成功。

用户希望 Web 版本先采用更直接的媒体交付方式：远程图用于缩略图与大图预览；需要本地副本时由浏览器下载；收藏默认触发下载。未来可能发布 Electron App，但本批不提前实现 App 下载管理器。

## 0.2 已确认目标

1. URL 型 Provider 结果保留为远程图片引用，不再要求 Node 媒体转存成功后 job 才能完成。
2. 列表显示缩略图；点击图片打开大图预览。
3. 大图右下角提供下载 icon。
4. 下载 icon 对所有可用图片常驻；点击后可以重复下载，不记录“已发起”或“已完成”。
5. 每次从“未收藏”切换到“收藏”时，默认同时发起一次浏览器下载。
6. 任务、Prompt、Provider 错误、模型和生成记录继续保留；远程链接过期后显示明确墓碑，不删除整条历史。
7. 继续优先复用系统/浏览器网络栈，不建设代理发现、PAC、Clash/Nikki 路由或 DNS 管理系统。
8. Provider 生成请求仍由服务端执行，API Key 不进入浏览器。

## 0.3 产品语义修正

### 下载状态

应用无法可靠确认：

- 用户是否在浏览器下载提示中取消；
- 文件是否最终成功写盘；
- 文件保存到哪个目录、是否被改名；
- 用户之后是否移动或删除了该文件。

因此本批不维护下载状态：下载 icon 常驻，不写数据库 timestamp，不显示“已下载/已保存”。若未来 Electron App 使用 `session.on('will-download')` 和 download item 事件，可以在 App 专属生命周期中增加真实完成状态，但不得把未来能力伪装成当前 Web 能力。

### 收藏状态

收藏和下载是两个不可原子提交的副作用：

- 收藏写入应用 SQLite，表达“用户希望保留这条生成来源”。
- 下载由浏览器执行，文件属于用户，不受应用数据库事务控制。

每次从未收藏切换到收藏时，前端必须在同一用户手势中发起真实下载链接，然后调用收藏 API。若收藏失败，已经下载的外部文件无法回滚；若浏览器阻止或用户取消下载，收藏仍可成功，常驻 icon 允许用户再次手动下载。实现和文案必须接受这一事实，不能声称“收藏与落盘原子成功”。

## 0.4 混合交付模型

| Provider 结果形态 | Web 交付策略 | 原因 |
|---|---|---|
| HTTPS URL | 保存远程引用；浏览器经同源受控路由预览/下载 | 避免 Node 媒体下载受代理与 Fake-IP 影响 |
| Base64 / Data URL | 延续现有后端校验与应用受管落盘 | 没有远程地址可供浏览器导航；长期把 Base64 放入 DB 不合适 |
| 既有本地图片 | 延续现有 `/api/images/:id` 本地流式读取 | 不破坏用户现有数据和收藏 |
| 未来 Electron | 复用相同 image source 数据模型，另加 Chromium 下载管理 | 本批不实现 |

当前 ZenMux、Gemini 和部分 Doubao 返回 Base64 或 Data URL；Fal、Qwen、Zhipu、SiliconFlow、Kling 等通常返回 URL。具体形态继续由各 Provider adapter 的私有 ModelSpec/解析器决定，不通过 Provider 名称硬编码业务分支。

## 0.5 明确不做

- 不把 Provider submit/poll 移到浏览器，不公开 API Key。
- 不让 Next.js 后端代理传输所有远程图片字节；否则仍回到 Node 网络栈和服务器带宽问题。
- 不自研通用代理层、自动检测 Shadowsocks/Clash/Nikki 端点、修改系统 DNS 或信任任意 Fake-IP。
- 不保证跨域远程 URL 一定出现“另存为”对话框；CDN 响应头不支持附件时，浏览器可能打开原图，界面需提示用户使用浏览器保存。
- Improve 1 不做 fetch-to-Blob 强制下载，因为它依赖媒体 CDN 的 CORS，仍不能覆盖所有 Provider，并会把整张图缓存在浏览器内存。
- 不自动把浏览器已下载文件重新导入应用；Web 页面不知道真实保存路径。
- 不处理视频、图片编辑、多图融合和 Electron 打包。

## 0.6 已确认结论

1. **已确认：下载 icon 常驻**。不记录下载请求或下载完成状态，用户可以随时重复下载。
2. **已确认：远程收藏的永久性边界**。永久保留收藏、Prompt、Provider、模型和生成记录；远程 URL 过期后显示“远程图片链接已过期”。只有浏览器下载的外部副本可能继续存在，应用不能保证还能展示它。

如用户要求“收藏后应用内永远能显示原图”，则必须恢复应用受管落盘或在 Electron 中接管下载并登记本地路径，不能只依赖远程链接和普通浏览器下载。
